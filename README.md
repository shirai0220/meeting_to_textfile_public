# 🎙️ Discord Meeting Logger & AI Transcription System

Discordでのテキストチャット記録と、AIによる高精度な音声文字起こしを組み合わせ、時系列順に統合された会議議事録を自動生成するシステムです。

ローカルPCで動作する軽量なDiscord Botと、Google Colaboratory（クラウド）上で動作するGPU活用の文字起こしプログラムの2つのコンポーネントで構成されています。

## 🌟 主な機能と特徴

### 1. リアルタイム・チャットロガー (`SimpleRecBot_4.py`)
- **メモリ最適化設計**: メッセージをメモリに溜め込まず、受信のたびにテキストファイルへ逐次書き込む（追記保存）ストリーミング処理に変更。長時間の会議でも極めて低負荷で動作し、OOM（メモリ不足）を防ぎます。
- **セキュアな認証**: トークンはソースコードにハードコードせず、外部ファイル（`config.txt`）から読み込む安全な設計を採用しています。

### 2. AI音声文字起こし＆ログ統合ツール (`音声文字起こしツール_ver4.2_公開用.ipynb`)
- **高精度文字起こし**: `faster-whisper` (large-v3-turbo) を使用し、複数人の音声を高速にテキスト化。
- **VAD (無音区間検出) とAIの幻覚フィルタリング**: 音声がない区間の推論をスキップして処理速度を向上。また、Whisper特有のハルシネーション（「ご視聴ありがとうございました」等の文脈を無視した定型文）をブラックリスト方式で自動除外します。
- **時系列の完全同期**: 録音Bot（Craig等）が生成する基準時間（UNIXタイムスタンプ）を利用し、音声ファイルの発言とテキストチャットのログを1つのタイムライン上にミリ秒単位でソートして統合します。

## 🛠️ 技術的な工夫（エンジニアリング・アプローチ）

* **環境起因エラーの独自ワークアラウンド解決**
  Google Colabの環境アップデートにより、AIモデルが依存するNVIDIA製GPUライブラリ（`.so`）のパスが通らなくなる問題が発生しました。これに対し、システムの環境変数をいじるのではなく、Pythonの `ctypes` と `glob` を活用してパッケージ内の動的ライブラリを探索し、メモリへ直接ロードするワークアラウンドを実装しました。
* **依存ライブラリのバージョン競合回避**
  最新の `PyAV` パッケージで発生した引数廃止による後方互換性エラー（`TypeError`）を防ぐため、インストール時にバージョン制限 (`av<19.0.0`) を明示的に指定し、安定稼働を担保しています。

## 🚀 使い方（ワークフロー）

本システムは、**ローカル環境（PC）**でのチャット記録と、**クラウド環境（Google Drive / Colab）**での音声解析を連携させて使用します。

### Step 1. Discord Botの準備と実行（ローカルPC）
1. 本リポジトリをローカルPCにダウンロードします。
2. `SimpleRecBot_4.py` と同じ階層に `config.txt` を作成し、Discord Botのトークンを1行だけ記述します。
3. コマンドプロンプトやターミナルでBotを起動します。
   ```bash
   python SimpleRecBot_4.py
   ```
4. Discord上で `!start` コマンドを送信すると記録が開始され、自動作成される `meeting_data` フォルダ内に `chat_log_YYYYMMDD.txt` が生成されます。会議が終わったら `!finish` で記録を終了します。

### Step 2. 音声データの取得（Discord）
会議中、Discordの録音ボット（Craigなど）を併用して音声を録音し、会議終了後に音声ファイル一式（ZIP形式など）をダウンロードしておきます。

### Step 3. Google Driveへのデータ集約（クラウド）
Google Driveのマイドライブ内に作業用フォルダ（例：`YourMeetingFolder/Data`）を作成し、以下の2つをアップロードします。
1. Step 1で生成したテキストログ (`chat_log_*.txt`)
2. Step 2で取得した音声データ (`*.zip` など)

### Step 4. 議事録の自動生成（Google Colab）
1. 本リポジトリの `音声文字起こしツール_ver4.2_公開用.ipynb` をGoogle Colaboratoryで開きます。
2. コード内の `DRIVE_FOLDER` のパスを、Step 3で作成したGoogle Driveのフォルダパスに変更します。
3. （任意）`USER_NAME_MAPPING` を編集し、アカウント名を表示名（Aさん など）に変換する設定を行います。
4. 全てのセルを上から順に実行します。処理が完了すると、対象フォルダの親ディレクトリに `Meetingkaigiroku/merged_minutes_YYYYMMDD.txt` として完成した統合議事録が出力されます。

## 📁 GitHub公開時の推奨 `.gitignore` 設定
このツールをフォークまたはクローンして利用する際は、個人情報や認証情報の漏洩を防ぐため、必ず `.gitignore` を設定してください。

```text
# 認証情報
config.txt

# ログファイル・データ保存フォルダ
meeting_data/
*.txt
```
